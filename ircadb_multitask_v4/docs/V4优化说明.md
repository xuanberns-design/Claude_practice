# V4 优化说明：稀疏视角条纹伪影与器官/病灶分割

本页依据你上传的 V3 运行结果（原样保存在 [用户提供的V3运行结果](用户提供的V3运行结果/)：`best.pt` 为 epoch 69，256 缓存，RCAB+PixelShuffle，测试患者 6/7/8）诊断问题，并说明 V4 每一项改动针对什么问题。**本包交付的是代码与配置，没有用你的真实 20 例数据重新训练**，因此下文不承诺具体的 SSIM/Dice 数值；真实提升必须按第 5 节重训后在测试集/五折折外结果上确认。

## 1. V3 结果诊断

### 1.1 重建：三名测试患者的等权平均

| 视角 | 参照 | FBP SSIM | V3 SSIM | FBP PSNR | V3 PSNR | FBP 肝区MAE | V3 肝区MAE |
|---|---|---:|---:|---:|---:|---:|---:|
| 32 | 原 CT | 0.612 | 0.718 | 18.18 | 24.25 | 64.6 | 18.5 |
| 64 | 原 CT | 0.696 | 0.751 | 23.32 | 25.94 | 29.7 | 16.7 |
| 128 | 原 CT | 0.776 | 0.789 | 25.86 | 27.06 | 14.7 | 14.9 |
| 32 | 1024角FBP | 0.645 | 0.877 | 18.83 | 27.81 | 62.8 | 10.1 |
| 64 | 1024角FBP | 0.786 | 0.927 | 26.45 | 31.95 | 25.7 | 7.2 |
| 128 | 1024角FBP | 0.958 | 0.966 | 39.04 | **35.23** | 5.5 | 4.8 |

体部区域（body_reference，以原 CT 为参照）SSIM：32 视角 0.270→0.476，64 视角 0.440→0.543，128 视角 0.601→0.616。

从这些数字可以得到四个结论：

1. **64/128 视角“提高不大”主要是参照上限，而不是模型失效。** 128 视角 FBP 与 1024 角 FBP 的 SSIM 已达 0.958，但两者与原 CT 只有约 0.78。也就是说，即使完美消除稀疏角误差，得到的也只是 1024 角 FBP，在原 CT 参照下仍只有约 0.78–0.80。原因有二：(a) 训练和推理在 256 网格进行，指标却在原生 512 网格计算，下采样再双线性上采样会损失细节；(b) 原 CT 自带的量子噪声纹理无法被任何重建预测，在 450 HU 窄窗中它主导了软组织 SSIM。V3 在 128 视角下已基本贴近这个上限。最终报告应改用原生 512 配置，并同时给出 1024 角 FBP 参照和区域指标。
2. **真正的问题在 32 视角。** 与原 CT 比较时，体部 SSIM 只有 0.476，这和你看到的明显条纹一致。V3 的重建网络只在图像域做后处理：缺失角度的信息不在输入中，而条纹是贯穿整幅图、与解剖结构重叠的方向性结构。有限感受野的 U-Net 在 256 patch 上训练时，只能在“残留条纹”和“过度平滑”之间折中。在 128 视角、以 1024 角 FBP 为参照时，V3 的 PSNR 反而比 FBP 低（35.2 vs 39.0 dB），说明图像域网络也会损伤本来已经很好的输入。
3. **patient 8 的全图 MAE 约 250 HU 是指标假象。** 128 视角 FBP 同样约 245 HU，而肝区只有约 13 HU，体部区域约 33 HU。原 DICOM 中存在超出 [-1000, 2000] HU、训练目标被截断的像素（通常在扫描视野外）。评估请以 body_reference/liver/tumor 区域和 1024 角 FBP 参照为主。
4. **旧 V2 的约 0.86** 与上表口径不同，不能直接比较（见 [结果诊断与改动依据](结果诊断与改动依据.md)）。

### 1.2 分割

| 视角 | 肝 Dice 均值 | 阳性肿瘤 Dice 均值 | patient 6（425 ml） | patient 8（10 ml） | 假阳性 ml（6/7/8） |
|---|---:|---:|---:|---:|---|
| 32 | 0.810 | 0.168 | 0.296 | 0.040 | 40.6 / 12.6 / 23.0 |
| 64 | 0.812 | 0.208 | 0.361 | 0.055 | 41.0 / 13.3 / 14.5 |
| 128 | 0.818 | 0.233 | 0.407 | 0.058 | 36.0 / 20.2 / 11.4 |

patient 7 的肝 Dice 只有 0.68–0.70。patient 6 的肿瘤 Dice 甚至低于 V2（V2 为 0.43/0.53/0.56）。原因如下：

1. **选模时分割欠训练。** V3 的分割前 30 轮在 clean 图上预训练，之后 30 轮逐步提高权重（epoch 60 才满权重），而 `best.pt` 是 epoch 69。选模分数中重建占 65%，门槛也只检查重建，所以选中的权重在分割还没收敛时就胜出了。
2. **小病灶几乎没有梯度。** Dice 按整批计算，会被大病灶主导，10 ml 级病灶的误差对损失贡献很小。
3. **没有利用标签结构。** 本包的标签定义是 `tumor = 原始肿瘤 ∩ 专家肝脏`（`dicom_io.load_patient`），即肿瘤必在肝内。但 V3 用逐像素 0.5 阈值直接输出，肝外散在假阳性、肝脏碎片和空洞都会原样计入 Dice 与假阳性体积。
4. 阈值固定为 0.5，没有在验证集上选择；分割网是容量较小的 plain U-Net，只有肝窗一个强度窗。

## 2. V4 重建改动：双域（正弦图 + 图像）重建

```
稀疏正弦图（仅已测角度）
  └─ 角度线性插值（利用 p(θ+180°,u)=p(θ,-u) 周期）
       └─ 正弦图 U-Net 残差补全缺失角度（角度周期填充）
            └─ 硬数据一致性：已测角度写回测量值
                 └─ 可微 FBP（与 skimage.iradon 逐像素一致）→ 双域图像
                      └─ 图像域 RCAB U-Net（膨胀上下文瓶颈），输入 [稀疏FBP, 双域图像, 视角] → 残差精修 → 输出
```

- **针对根因。** 条纹来自缺失角度。先在正弦图域用网络补全缺失角度，再做 FBP，从源头上减少条纹。图像网络只需修复少量残余误差，不必再猜测被条纹覆盖的解剖结构。在合成数据上，即使不训练，只做“角度插值 + 数据一致性 + FBP”，图像误差也比稀疏 FBP 低很多（见第 4 节）。
- **不编造与测量矛盾的结构。** 已测角度强制保持测量值，网络只能修改缺失角度。训练时另外加入投影一致性损失：输出图重投影到已测角度后，必须与测量值吻合。
- **算子精确。** [src/ct_ops.py](../src/ct_ops.py) 用 `grid_sample` 实现投影和 FBP，与 skimage `radon`/`iradon(circle=False)` 的相对误差约 1e-6（单元测试覆盖奇数和偶数尺寸）。缓存补充正弦图后，会逐患者、逐视角复核“正弦图子集的 FBP = 已缓存稀疏 FBP”，误差超过 1 HU 即报错停止。
- **整图训练与精确增强。** FBP 是整幅图算子，双域模式不再做 256 patch 训练，条纹的全局上下文完整保留。几何增强使用绕投影中心的镜像和 90° 旋转，正弦图按解析关系同步变换（已用 skimage 重投影验证逐元素一致）。
- **损失。** 缺失角度正弦图 L1、双域中间图器官加权 L1、体部频域 L1（直接惩罚方向性高频条纹），以及原有的 HU L1/MSE/SSIM/梯度/FBP 退化惩罚。
- **优化。** 参数 EMA（0.999），验证和保存都用 EMA 权重；学习率先线性预热 5 轮，再余弦退火。

## 3. V4 分割改动

| 问题 | 改动 |
|---|---|
| 选模时分割欠训练 | `selection_start_epoch: 40`（= 预训练 20 + 渐增 20），分割满权重后才开始选 best.pt；`selection_reconstruction_weight` 从 0.65 降到 0.5 |
| 分割网容量/上下文不足 | `seg_backbone: resattn`：残差通道注意力编码器、膨胀上下文瓶颈、注意力门跳连（抑制血管/条纹响应）、1/8~1/2 深监督 |
| 小病灶梯度弱 | 肿瘤**逐样本** Focal-Tversky（β=0.7 偏召回），并保留原有 BCE/Dice、边界、肝外难负样本 |
| 肿瘤与肝脏不一致 | 肿瘤头以肝概率为条件，并加层级一致性损失 p(tumor) ≤ p(liver) |
| 单一窗宽 | 在肝窗之外增加 [-500, 500] HU 宽窗输入 |
| 逐像素阈值、碎片与肝外假阳性 | 3D 后处理：肝取最大连通域 + 逐层填洞；肿瘤只保留在“预测肝 + 5 mm”内；删除小碎片；liver ∪= tumor |
| 阈值没有调 | 训练结束后**只在验证集**上搜索肿瘤阈值（0.3–0.7）和最小体积（0–0.5 ml），写入 `postprocess.json`，测试时直接套用 |
| 推理稳定性 | 分割四向翻转 TTA |

评估 CSV 的主列是后处理后的结果，同时保留 `*_raw`（纯阈值）列作对照。新增 `liver/tumor_HD95_mm`、`*_ASSD_mm` 以及病灶级 `tumor_lesion_recall/precision`，可以单独观察 patient 8 这类小病灶是否被检出。

## 4. 合成数据消融（仅验证方法方向，不代表真实患者数值）

运行 `python -m tests.benchmark_dual_vs_image --steps 1500`：64×64 随机腹部椭圆体模，16 个稀疏视角，128 角补全；两种方法使用相同训练集（400 例）、步数、学习率与测试集（60 例），指标在 [-200, 250] HU 窗内计算：

| 方法 | SSIM | PSNR dB | MAE HU | CPU 训练时间 |
|---|---:|---:|---:|---:|
| 稀疏 16 角 FBP | 0.549 | 18.41 | 97.3 | — |
| 角度插值+数据一致性+FBP（未训练） | 0.576 | 19.79 | 36.1 | — |
| V3 图像域 U-Net（1500 步） | 0.913 | 31.61 | 10.4 | 161.1 s |
| V4 双域（1500 步） | 0.922 | 32.33 | 7.9 | 455.5 s |

结论（单一随机种子，合成体模）：同等步数下，V4 双域在三项指标上都优于 V3 图像域后处理，MAE 下降约 24%（10.4→7.9 HU），PSNR 提高 0.7 dB。代价是每步计算量约为 2.8 倍。仅做“角度插值 + 数据一致性”而不训练，就能把 MAE 从 97 HU 降到 36 HU，说明补全缺失角度确实针对条纹的来源。这些体模比真实腹部 CT 简单得多，差距在真实数据上可能更大，也可能更小，只能由你的真实数据重训确认。原始输出见 [benchmark_dual_vs_image.json](benchmark_dual_vs_image.json)。

## 5. 使用步骤

### 5.0 零重训快速收益：给现有 V3 权重加 3D 后处理

后处理参数属于推理专用参数，已有 checkpoint 无需重训。在 V3 run 的 `resolved_config.yaml` 中加入一行 `postprocess: true`（建议另存一份，例如 `runs/joint_enhanced256/resolved_config_pp.yaml`），然后运行：

```powershell
python -m src.cli --config runs/joint_enhanced256/resolved_config_pp.yaml tune-postprocess --checkpoint runs/joint_enhanced256/best.pt
python -m src.cli --config runs/joint_enhanced256/resolved_config_pp.yaml evaluate --checkpoint runs/joint_enhanced256/best.pt --split test --no-export
```

这一步只能减少假阳性和碎片，不能修复重建条纹。

### 5.1 V4 首选：复用现有 256 缓存

先修改 [configs/v4_dualdomain_256.yaml](../configs/v4_dualdomain_256.yaml) 的 `data_root`。`cache_dir` 默认就是 V3 实际使用的 `cache/quality256_newlabels`，所以 prepare 只会就地补充正弦图（约 1 GB），不会重做审计、划分和投影。

```powershell
python -m src.cli --config configs/v4_dualdomain_256.yaml prepare
python -m src.cli --config configs/v4_dualdomain_256.yaml train
python -m src.cli --config configs/v4_dualdomain_256.yaml evaluate --checkpoint runs/v4_dualdomain256/best.pt --split test
```

训练结束后会自动在验证集上生成 `runs/v4_dualdomain256/postprocess.json`，evaluate 会自动读取它（仅当它属于同一 checkpoint）。显存不足时使用 [configs/v4_dualdomain_256_low_memory.yaml](../configs/v4_dualdomain_256_low_memory.yaml)。

### 5.2 最终报告：原生 512

[configs/v4_dualdomain_native512.yaml](../configs/v4_dualdomain_native512.yaml) 需要新的 512 缓存。按 README 的流程运行 `audit`、`split --base-split <旧 splits.json>`、`prepare`、`train`、`evaluate`。512 下训练必须整图进行（batch 2 + AMP）。

### 5.3 五折

与 README 相同，把 `--config` 换成 V4 配置即可：`cv-init` → `cv-train`（每折训练后自动在本折验证集调后处理）→ `cv-evaluate` → `cv-aggregate`。

## 6. 成本与注意事项

- 双域模式每步要做一次 C 层稠密角 FBP，训练速度约为 V3 256-patch 的 1/2～1/3。512 配置更慢，需要更大显存；显存不足时依次减小 batch_size、base_channels（32→24→16）和 sino_dense_views（512→256）。每次改动都属于新实验。
- 显存数字是估计值，本包只在 CPU 上验证了流程。
- `infer` 用于无真值数据时，双域模型需要同一协议下的稀疏正弦图（`--sinogram`，形状 `[Z, views, D]`）。`--reproject-fbp` 只是没有正弦图时的近似，质量会下降，结果文件会注明来源。
- V3 的 checkpoint 仍可用 V4 代码评估（image 模式的权重键不变）。V3 的 last.pt 不能用 V4 续训，因为学习率调度和 EMA 协议不同。
- 本任务的 tumor 定义为“肝内部分”。如果将来改为包含肝外病灶，应把 `tumor_liver_margin_mm` 设为 null，并关闭 `seg_hierarchy_weight`。
